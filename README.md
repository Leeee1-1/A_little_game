# A Little Game

一个基于 Python 实现的多人牌类博弈小游戏。

本项目目前以**命令行（CLI）**作为主要交互方式，实现了从洗牌、发牌、玩家行动、开牌比牌、玩家淘汰到底池结算的完整基础游戏流程。

项目的核心目标不是制作一个复杂的商业游戏，而是以一个相对简单的博弈环境作为实验平台，为后续研究**策略决策、AI 代理、统计实验与强化学习**提供基础。

---

## 1. 项目特点

目前已经实现：

* 标准 52 张扑克牌生成与发牌
* 多名玩家参与游戏
* 每名玩家拥有独立筹码
* 玩家可以选择是否看牌
* 明牌与闷牌具有不同的行动规则
* 跟注
* 开牌
* 强开
* 闷开
* 弃牌
* 根据牌力比较胜负
* 玩家出局机制
* 动态维护场上存活玩家
* 底池（`accumulated_bet`）管理
* 最终胜者获得底池
* 命令行游戏状态播报与手牌显示

当前版本的游戏核心逻辑全部运行在 Python 中。

---

# 2. 游戏基本流程

游戏开始后：

```text
创建牌堆
   ↓
创建玩家
   ↓
发牌
   ↓
玩家依次行动
   ↓
玩家下注 / 开牌 / 弃牌
   ↓
失败玩家出局
   ↓
刷新场上存活玩家
   ↓
只剩一人
   ↓
游戏结束
   ↓
胜者获得底池
```

---

# 3. 玩家与筹码

每名玩家拥有：

* 姓名
* 筹码（`chips`）
* 手牌（3 张）
* 是否已经看牌（`seen`）
* 是否仍在游戏中（`active`）

游戏过程中：

```text
active = True
```

表示玩家仍然在场。

```text
active = False
```

表示玩家已经出局。

底池统一由：

```python
accumulated_bet
```

进行管理。

玩家投入筹码后：

```text
player.chips ↓
accumulated_bet ↑
```

最终游戏结束时，最后一名存活玩家获得整个底池。

---

# 4. 看牌与闷牌

玩家每次轮到自己行动时，如果尚未看牌，需要首先选择：

```text
是否看牌？
1. yes
2. no
```

## 4.1 看牌

选择 `yes` 后：

* 玩家将 `seen` 设置为 `True`
* 系统显示该玩家的三张手牌
* 玩家进入明牌行动阶段

明牌玩家可以：

```text
1. 跟注
2. 开人
3. 弃牌
```

---

## 4.2 闷牌

选择 `no` 后：

玩家不会看到自己的手牌，并进入闷牌行动阶段。

可以：

```text
1. 闷跟
2. 闷开
```

闷牌与明牌的下注成本不同。

---

# 5. 跟注规则

## 5.1 明牌跟注

已经看牌的玩家跟注：

```text
2 × bet
```

当前默认：

```text
bet = 10
```

因此明牌跟注需要：

```text
20 chips
```

---

## 5.2 闷牌跟注

尚未看牌的玩家闷跟：

```text
1 × bet
```

默认需要：

```text
10 chips
```

---

# 6. 开牌规则

开牌时，玩家需要从当前仍处于 `active` 状态的玩家中选择一名目标。

已经出局的玩家不能成为开牌目标。

---

## 6.1 开明牌玩家

如果目标玩家已经看牌：

```text
open_cost = 2 × bet
```

默认：

```text
20 chips
```

---

## 6.2 开暗牌玩家

如果目标玩家尚未看牌：

```text
open_cost = 4 × bet
```

默认：

```text
40 chips
```

因此，开暗牌玩家的成本高于开明牌玩家。

---

# 7. 筹码不足与强开

如果玩家选择需要支付固定金额的行动，但当前筹码不足，则不能正常完成该行动。

例如：

```text
明牌跟注需要 20
玩家只有 13
```

此时不能正常跟注。

如果规则允许，则进入强制结算/强开逻辑。

---

## 7.1 强开

强开时，玩家将自己当前剩余筹码全部投入：

```python
open_cost = player.chips
```

然后：

```text
player.chips = 0
```

并使用这部分筹码完成比牌。

如果强开者获胜：

```text
返还本金 + 等额 bonus
```

即：

```text
player.chips += 2 × open_cost
```

bonus 来自底池。

如果强开者失败：

```text
player.active = False
```

玩家出局。

---

# 8. 闷开

闷开与强开的核心区别在于：

> 闷开获胜只返还本金，不产生 bonus。

闷开所支付的金额为：

```python
open_cost = min(player.chips, 2 * bet)
```

因此：

* 筹码足够支付 `2 × bet` 时，支付 `2 × bet`
* 筹码不足时，投入全部剩余筹码

如果闷开获胜：

```text
返还 open_cost
```

即玩家只是拿回自己投入的本金。

不会额外获得 bonus。

如果闷开失败：

```text
player.active = False
```

玩家出局。

---

# 9. 弃牌

玩家可以主动选择弃牌。

弃牌后：

```python
player.active = False
```

玩家立即退出当前游戏。

已经投入底池的筹码不会因为弃牌而返还。

---

# 10. 比牌

玩家进行开牌后，由 `hand.py` 中的牌型评价与比较函数决定胜负。

核心函数：

```python
evaluate_hand()
compare_hands()
```

玩家之间通过手牌牌力进行比较。

当前版本暂未单独实现平局（Tie）的独立处理规则。

---

# 11. 玩家淘汰

玩家在以下情况下可能出局：

* 开牌失败
* 强开失败
* 闷开失败
* 主动弃牌

出局时：

```python
player.active = False
```

游戏会动态重新计算：

```python
active_players = [p for p in players if p.active]
```

因此已经出局的玩家不会继续参与后续行动，也不能成为新的开牌目标。

---

# 12. 游戏结束

每轮行动后都会重新检查当前仍然存活的玩家。

当：

```python
len(active_players) == 1
```

说明只剩下一名玩家。

此时游戏结束。

最后存活的玩家成为本局赢家，并获得：

```python
accumulated_bet
```

中的全部筹码。

随后：

```python
winner.chips += accumulated_bet
accumulated_bet = 0
```

完成底池结算。

# 13. 项目结构

当前项目主要由以下模块组成：

```text
A_little_game/
│
├── deck.py
├── hand.py
├── player.py
├── round.py
├── README.md
└── LICENSE
```

### `deck.py`

负责：

* 创建牌堆
* 洗牌
* 发牌

主要数据流：

```text
Deck → deal() → Player.hand
```

---

### `hand.py`

负责：

* 手牌评价
* 牌型判断
* 两名玩家之间的牌力比较

核心函数：

```python
evaluate_hand()
compare_hands()
```

---

### `player.py`

负责：

* 玩家对象
* 玩家状态
* 玩家筹码
* 玩家手牌
* `active`
* `seen`

---

### `round.py`

负责整个游戏回合：

* 玩家行动
* 跟注
* 开牌
* 强开
* 闷开
* 弃牌
* 玩家淘汰
* 底池管理
* 游戏结束
* 最终结算

目前 `round.py` 是整个项目的核心控制模块。

确保已经安装 Python。

进入项目目录：

```bash
cd A_little_game
```

```bash
python round.py
```

# 15. 当前版本定位

当前版本首先追求的是：

> **完整、可运行、规则闭环的最小可玩版本（MVP）。**

因此目前仍然保留了一些明显可以改进的地方，例如：

* 游戏逻辑仍然集中在 `round.py`
* 部分行动逻辑存在较深的 `if / elif / while` 嵌套
* 输入处理仍然主要依赖命令行
* 平局规则尚未独立定义
* 游戏目前主要面向固定数量玩家
* 尚未实现 AI 玩家
* 尚未实现图形化前端
* 尚未实现多局制游戏

这些问题将在后续版本逐步处理，而不会为了追求代码结构上的“完美”而提前过度设计。
